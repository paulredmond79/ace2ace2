# Safety

This document describes all safety considerations for the ACE Bridge project.
Safety is a first-class concern because the bridge operates on RS485 buses
connected to live printer hardware. Mistakes can damage hardware or cause
unexpected printer behaviour during a print job.

---

## Safety Principles

1. **Never transmit what you don't understand.** If a packet's purpose is uncertain,
   do not send it. Log it, study it, understand it first.

2. **Fail safe.** On any error, ambiguity, or timeout, stop transmitting and
   log the reason. Never retry indefinitely.

3. **Read-only first.** Always begin with `read_only: true` in config. Switch to
   bidirectional only after verifying correct packet reception.

4. **Never assume pinout.** Always measure voltage and ground before connecting.

5. **Never assume voltage level.** RS485 at 5V will damage 3.3V GPIO.

---

## Pre-Connection Checklist

### Before First Hardware Connection

- [ ] Power off ALL devices (printer, ACE 2 Pro, ACE Pro, Raspberry Pi)
- [ ] Discharge any capacitors (wait 30 seconds after power-off)
- [ ] **Verify ACE 2 Pro connector pinout** against `docs/Hardware.md` before inserting
      any cable — probe Pin 2 (expected RS485 A) and Pin 1 (expected RS485 B) against
      Pin 4 (GND) to confirm orientation and signal type
- [ ] **Verify ACE Pro connector pinout** — confirm Pin 2 = D−, Pin 3 = D+, Pin 5 = GND
      before completing custom cable (see `docs/Hardware.md` for full pinout)
- [ ] Measure RS485 A line to GND with multimeter (AC and DC)
- [ ] Measure RS485 B line to GND with multimeter (AC and DC)
- [ ] Measure RS485 A to B differential voltage
- [ ] Confirm voltage is within spec of RS485 transceiver being used
- [ ] Confirm common ground between Pi and RS485 bus
- [ ] Confirm RS485 transceiver DE/RE pins are not driven HIGH (Pi starts in receive mode)
- [ ] Confirm `read_only: true` in `config/config.yaml`
- [ ] Confirm `simulate: false` is NOT set (should be `true` for first test)

### Before Connecting ACE Pro USB

- [ ] Check USB current requirements (measure or read spec)
- [ ] Ensure USB hub or Pi USB port can supply required current
- [ ] Confirm USB cable is data-capable (not charge-only)

## Software Safety Features

### Read-Only Mode

Set `bridge.read_only: true` in config. In this mode:
- RS485 TX is never asserted
- RS485 DE pin is held LOW (receive only)
- All received packets are decoded and logged
- No commands are sent to ACE Pro

Use this mode for:
- Initial hardware validation
- Capture sessions
- Any time you are uncertain about the protocol

### Simulate Mode

Set `bridge.simulate: true` in config. In this mode:
- No hardware is opened
- All packets are generated by internal simulation
- Useful for testing without hardware
- Does not affect real devices

### Emergency Transmit Disable

CLI command:
```bash
bridge stop-tx
```

This immediately drives DE LOW and stops all RS485 transmission without
stopping the bridge (packet reception and logging continue).

To re-enable:
```bash
bridge enable-tx
```

### Packet Validation

Before any packet is transmitted:
- Framing is validated (start byte, length, end byte)
- CRC is recalculated and verified
- Address is confirmed to be the bridge's own address
- Packet type is in the known-good whitelist

Any validation failure causes the packet to be dropped and logged with `ERROR`.

### Timeout Handling

If no response is received from ACE Pro within the configured timeout:
- Do NOT retry indefinitely
- Log the timeout with full packet context
- Return an error response to the printer if protocol allows
- Increment error counter; halt TX if error rate exceeds threshold

## RS485 Bus Safety

### Half-Duplex Control

RS485 is half-duplex. The DE (Driver Enable) and RE (Receiver Enable) pins must be
controlled carefully:
- DE HIGH enables transmit (disables receive)
- RE LOW enables receive (must be asserted)
- DE must be driven LOW within N microseconds after last TX byte

Failure to control DE correctly will cause bus contention and corrupt packets from
other devices on the bus.

The software uses a strict transmit window:
1. Assert DE HIGH
2. Write bytes
3. Wait for UART to drain (hardware buffer empty)
4. Assert DE LOW
5. Resume receive

### Bus Contention

If the bridge transmits at the same time as another device, both packets are corrupted.
The capture layer detects this by looking for framing errors on received packets.

### Termination

Do not add termination resistors unless the bus is unterminated and shows signal
integrity problems (check with oscilloscope first). Adding incorrect termination
degrades the signal.

## Operational Safety

### During a Print Job

**Do not restart the bridge during an active print.** The printer may be in the middle
of a filament load/unload sequence. An unexpected disconnect may cause:
- Filament jam
- Failed print
- Printer error state

Wait for the printer to be idle before restarting or reconfiguring the bridge.

### Firmware Updates

Do not apply ACE Pro firmware updates while the bridge is running. The USB connection
will be reset and may leave the bridge in an undefined state.

## Error Conditions and Response

| Error | Response |
|-------|----------|
| CRC validation failure (received) | Log, discard packet, increment counter |
| CRC validation failure (to send) | Log at ERROR, drop packet, do not transmit |
| RS485 framing error | Log, discard, check baud rate config |
| USB disconnect | Log at ERROR, stop all TX, attempt reconnect with backoff |
| ACE Pro timeout | Log, return error to printer if possible, do not retry indefinitely |
| RS485 bus error | Log, assert DE LOW, stop TX |
| Config validation failure | Refuse to start, print error |
| Unknown packet type | Log hex dump, pass through in bridge mode, flag for research |

---

## Logging

All safety-relevant events are logged at `ERROR` or `WARNING` level and include:
- Timestamp (microseconds)
- Direction (upstream/downstream)
- Raw hex bytes
- Decoded fields (if available)
- Error reason

Safety events are never silently swallowed.
